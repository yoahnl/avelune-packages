# Avelune Packages — consignes communes aux agents

Avant de travailler sur un pack, le registre, une galerie, le site ou une release, lire [le skill Avelune Packages](skills/avelune-packages/SKILL.md). C’est la référence commune, utilisable comme document même lorsque l’outil ne reconnaît pas les skills.

Lire ensuite le `README.md`, `catalogue.json`, les manifestes concernés et l’état Git actuel. Les données et les preuves fraîches font foi pour les versions, les comptes et les qualifications.

Conserver le site unique, son dark mode et son identité officielle. Ne pas créer un autre site ou publier un dossier candidat simplement parce qu’il existe. Les instructions détaillées et leurs chemins de référence sont dans le skill.

Les demandes explicites de l’utilisateur restent prioritaires. Ce document n’autorise ni commit, ni push, ni release, ni déploiement, ni changement d’accès. Préserver les travaux des autres conversations ; ne pas lancer d’import ou d’export concurrent.

Le moteur Avelune vit dans un autre dépôt. Pour ses API ou les projets Studio, lire également ses instructions propres ; les conventions du site ne remplacent pas les règles d’édition canonique.
